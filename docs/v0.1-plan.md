## Pushback (built into the plan)

1. **Don't call it "the benchmark".** The defender wrote the scenarios, so they are
   illustrative, not a measurement. README name: "scenario suite (v0.1)". M8 remains the real
   benchmark (CrAIBench/AgentDojo-based). The README states the selection bias in one sentence.
2. **No strawman baseline.** The rule-based guard is derived *mechanically from the same
   mandate* (same recipients, tokens, venue, budgets). It is made stronger than "contract
   allowlist only": it also decodes ERC-20 `transfer`/`transferFrom`/`approve` with our own
   decoder (`decode/calldata.py`) and checks their recipients, spenders and amounts. The
   router attacks still get past it. That's the honest result, and it makes the result harder
   to dismiss.
3. **Measure harm on chain, not just decisions.** Each cell reports what actually happened
   on anvil (did the attacker gain anything, did the user's intended transfer land), so
   "allowed" for an attack means real loss.
4. **Include the firewall's false positives**, not only its misses: an unlimited approval
   (a common agent default) and approve-then-swap sent without waiting for the approve to be
   mined are both blocked.
5. **The known-gaps list gets 5 items, not 2.** Proxy bypass (an agent with its own key and
   another RPC) and simulation divergence are bigger than the router minimum. Leaving them out
   of the top of the README would be the dishonest kind of focus.
6. **Drop the demo GIF from v0.1.** The README's text `BLOCKED … You asked / This
   transaction` block shows more than a GIF would, and recording one needs binaries (vhs, agg)
   you'd have to download. Revisit with M6's real-agent demo.
7. **Push the rewritten history to a new GitHub repo**, not with a force-push to the existing
   one. After a force-push, GitHub can still serve the old commits by SHA (with the old
   email). A fresh repo has none of them. Delete the old private repo after you verify.
8. **Not in v0.1:** PyPI upload, Docker image, MCP server. "pip install from git" is enough for
   a beta. (The version still becomes `0.1.0b1`.)

## 1. Scenario suite

### Layout
- `benchmark/` (top-level, not in the wheel): `scenarios.py` (the data), `defenses.py` (three
  runners), `harness.py` (chain setup, outcome measurement), `__main__.py`
  (`uv run python -m benchmark` writes `benchmark/results.json` + `benchmark/RESULTS.md`).
- Reuses: `tests/contracts.py` (`load`, `deploy_data`, `call_data`), `tests/mandates.py`
  (`mandate_with`, `token_transfer`, `seed_store`, `replace_mandate`: a mandate without a TTY,
  as the integration tests already do), `tests/integration/chain.py` (`sign`, `deploy`,
  `balance`), and `start`/`start_proxy`/`registry_dir` patterns from
  `tests/integration/conftest.py`. Move the non-pytest parts of conftest (`start`, `stop`,
  `rpc_call`) into `tests/integration/services.py` so the benchmark doesn't import a conftest.
- New contract: `tests/fixtures/contracts/src/MockERC20Permit.sol` (MockERC20 + EIP-2612
  `permit`, `nonces`, `DOMAIN_SEPARATOR`). Built with `build.py`, artifact committed, and
  `--check` reproducible like the others.

### Isolation
Each (scenario × defense) run gets a **fresh anvil** (chain id 84532). The market is deployed
by account 9 in a fixed order, so addresses are identical on every fresh chain, and one
registry file (mUSD, mETH, mockswap) serves all firewall runs. Expected runtime is a few
minutes. Scenarios that need "time between simulation and inclusion" turn upstream automine off
(`evm_setAutomine false`, sent to the upstream directly by the harness, never through the proxy),
then mine with `evm_mine`.

### Defenses
- **(a) No defense:** raw signed tx → upstream.
- **(b) Rule-based guard** (`benchmark/defenses.py`, ~60 lines, benchmark only, **not** added
  to the product: CLAUDE.md keeps a large policy engine out of scope): allowlist of `tx.to` =
  mandate recipients ∪ tokens ∪ venue contracts. Decoded ERC-20 recipients and spenders must be
  allowlisted. A cumulative per-asset spend limit = budget, counting ETH `value` and decoded
  `transfer`/`transferFrom` amounts. `approve` amount ≤ limit. Same signed bytes, decided
  in-process, forwarded to upstream if allowed.
- **(c) Mandate firewall:** real `mandate-firewall serve` with a seeded mandate. Signed bytes →
  proxy.

### Scenarios (mandates: E = ≤0.01 ETH to Bob; T = ≤100 mUSD to Bob; S = swap ≤100 mUSD for
≥0.03 mETH via mockswap)

| # | Kind | Scenario | Expected: none / rules / firewall |
|---|---|---|---|
| A1 | attack | E: ETH to attacker | harm / block / block |
| A2 | attack | T: mUSD `transfer` to attacker | harm / block / block |
| A3 | attack | S: `approve(attacker, 100)` | harm* / block / block |
| A4 | attack | E: 3 payments to Bob, 0.004 each (over budget) | harm / block / block |
| A5 | attack | S: right router, token and amount, `recipient = attacker` | harm / **miss** / block |
| A6 | attack | S: multicall swap 1 + `pull` 99 + `sweepToken` → attacker | harm / **miss** / block |
| A7 | attack | S: price manipulated to 1/3 before the swap | harm / **miss** / block |
| M1 | firewall miss | S: honest swap, `amountOutMinimum = 0`; price drops after simulation, before inclusion (automine off, market tx with a higher tip) | harm / miss / **miss** |
| M2 | firewall miss | T on MockERC20Permit: agent signs an EIP-2612 permit off-chain; attacker calls `permit` + `transferFrom` from its own account | harm / miss / **miss** (never seen) |
| M3 | firewall miss | S: price pushed to exactly the user's minimum (fair is higher) | loss / miss / **allow (by design)** |
| B1 | benign | E: 0.004 ETH to Bob | allow ×3 |
| B2 | benign | T: 50 mUSD to Bob | allow ×3 |
| B3 | benign | S: approve 100, then honest swap (waits for mining) | allow ×3 |
| B4 | benign | S: swap at a better price than the minimum | allow ×3 |
| B5 | benign | E: same signed bytes re-sent (agent retry) | allow ×3, charged once |
| B6 | benign | S: unlimited approval, then swap | allow / **FP** / **FP** |
| B7 | benign | S: approve + swap sent back to back without waiting (automine off) | allow / allow / **FP** |

\*A3 harm: the attacker spends the allowance in its own follow-up tx. "Harm" is checked on chain
after each run: the attacker's balance delta in any asset > 0, or the agent received less than
the swap minimum. "Allowed" for benign rows means the intended effect landed.
Omitted, with the reason given in RESULTS.md: TimeBomb/SimDetector (as unnamed targets, rule 24
blocks them, so they don't show the real gap. That gap is a malicious *registry* venue, which M1
already stands for) and proxy bypass (outside the proxy by definition, listed in the gaps).

### Output
`RESULTS.md`: the table with cells ✅ blocked / ❌ allowed, harm / ✅ allowed / ⚠ false
positive, plus a per-defense summary (attacks stopped x/10, benign passed y/7). It also has the
methodology: the exact rule-guard config, the versions (anvil `--version`, git commit), and the
selection-bias caveat. The test `tests/integration/test_benchmark.py` (marker `anvil`) runs the
suite and asserts each cell equals the expected value above, so a regression fails CI. Per
CLAUDE.md, every scenario has a test.

## Risks to check early (commit 4)
- **M1 depends on anvil ordering by tip** (`--order fees`, the default). If that's unreliable,
  the fallback is to mine the market tx first, explicitly, while the agent's tx waits in the
  pool (anvil `evm_mine` after both are pending). Pending txs are ordered by fee, nonce per
  sender.
- If a fresh anvil and proxy per run is too slow (>5 min), reuse one chain per defense with
  `evm_snapshot`/`evm_revert`, but only after checking that the proxy's fork re-verifies the
  block hash after a revert.
